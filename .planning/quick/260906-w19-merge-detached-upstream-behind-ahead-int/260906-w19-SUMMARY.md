# Quick Task 260906-w19: Merge git sync indicators into one mutually exclusive subsegment Summary

**One-liner:** `seg_git` now renders exactly one sync token per state — green `≡` in-sync, blue `↑A` ahead, yellow `↓B` behind, red pair when diverged, red `≢` no-upstream, magenta SHA when detached — plus a cyan stash count; suite grew 220 → 224 checks, four live spec docs updated.

## What was done

### Task 1: Rework seg_git sync subsegment + update test suite (commit 4a59567)

- Replaced the independent `≡`/`≢` + `↓` + `↑` appends in `seg_git` with one bash-3.2-safe if/elif chain implementing 6 mutually exclusive states. Per-token coloring kept: the diverged pair renders as two separate red spans with a plain space between (PROJECT.md one-colored-unit convention).
- Detached behavior byte-identical to before: magenta short-SHA label, no sync glyph (D-24/D-25 kept, per the user's correction in CONTEXT).
- Stash append changed from `${DIM}#` to `${CYAN}#`.
- Comment block above `seg_git` rewritten to describe the new scheme.
- Untouched as planned: dirty detection, porcelain parsing, unborn-branch handling (falls into `≢` naturally), stash counting, `GIT_OPTIONAL_LOCKS=0`.
- Tests: boundary-ones and full-form stripped expectations lost the `≡`; byte check now asserts `[31m↓2 [31m↑3 [36m#2`; check name renamed to the new colors. Added two new scenarios (4 checks): ahead-only blue (`[34m↑1` + stripped `main ↑1`, then `reset --hard origin/main` restores in-sync) and behind-only yellow (`[33m↓1` + stripped `main ↓1`, placed between the fetch and the local commit). Palette whitelist unchanged (34m/36m already listed).

- `README.md`: example line drops `≡`; legend reworked — `≡`/`≢` row explains mutual exclusivity and colors; `↓`/`↑`/`#` rows carry yellow/blue/red-pair/cyan.
