# Quick Task 260912-x11: Close the Timezone Test Gap Summary

Made the suite able to fail when the shipped timezone path breaks, and made that property itself
checkable — four sub-hour zones now render end to end against libc, and a mutation gate proves a
broken offset turns the suite red.

## What Was Done

### Task 1 — Non-UTC end-to-end block in `tests/run.sh` (WR-01)

Commit `61852cc`. New section 4b sits between section 4 and section 5, reusing section 4's `dfmt`
oracle and its `now` / `t5` / `t7` instants. A four-row `:`-delimited table drives two checks per
zone:

| Zone | Offset | Why this zone |
|------|--------|---------------|
| `Asia/Kolkata` | `+0530` | no DST, sub-hour |
| `Asia/Kathmandu` | `+0545` | no DST, 45-minute |
| `Australia/Eucla` | `+0845` | no DST, 45-minute |
| `Pacific/Marquesas` | `-0930` | no DST, sub-hour, western sign |

1. `zone database present: TZ=<zone> -> <offset>` — asserts the host really resolved the zone. A
   runtime without tzdata resolves any unknown TZ to UTC; the oracle and the script would then
   agree at UTC and check 2 would pass while proving nothing.
2. `non-UTC render TZ=<zone>: ...` — renders the real script with a `TZ=<zone>` command prefix
   (overrides the global `TZ=UTC` pin for that one command only) and matches the ANSI-stripped
   line 2 against expectations taken from libc under the same zone.

The `non-UTC render` name prefix is a contract with Task 2 and is commented as such in the source.

### Task 2 — `tests/mutation-tz.sh` (WR-01 acceptance bar)

Commit `6e56382`. New standalone, opt-in script, mode 0755. Per mutant it creates a `mktemp -d`
scratch tree, copies `kit/` and `tests/` into it, rewrites the `TZOFF=` assignment with `awk`
(never `sed -i`), guards applicability with `cmp -s` against the pristine source, runs the copied
suite, and passes only when the suite exits non-zero **and** at least one
`FAIL non-UTC render` line appears.

| Mutant | Replacement | Result |
|--------|-------------|--------|
| `offset dropped` | `TZOFF=0` | **killed** — 4 non-UTC render checks went red |
| `offset rounded to hours` | `TZOFF=$(( $(tz_offset_secs ...) / 3600 * 3600 ))` | **killed** — 4 non-UTC render checks went red |

The second mutant is what makes the sub-hour zone table mechanically load-bearing: no whole-hour
zone could detect it.

### Task 3 — Two sandbox assertions that can go red (WR-05, WR-06)

Commit `de97c1e`.

- **§5.14 (WR-05):** the folded `date '+%s %z'` probe now ends in `check_ok`, so its result reaches
  `CHECKS` / `FAILS` and the summary line. The `INFO` evidence line stays. The banner comment no
  longer calls the probe informational — it states that an unparseable shape silently pins every
  reset clock in the container to UTC.
- **§5.13 (WR-06):** the Fable assertion is re-pinned with four end-anchored `case` arms instead of
  "a percent sign somewhere": no slot at all, `% now`, `% HH:MM`, `% Ddd HH:MM`. The no-slot arm is
  required — `fetch_usage` sets `F_PCT` and `F_RST_ISO` independently, so percent-without-`resets_at`
  is a legitimate render (D-69). The credentials-absent branch and the cache evidence line were left
  alone.

Both shape guards were probed against a throwaway sample table before committing: the four
legitimate Fable renders accept; garbled (`% 1:5`), spelled-out (`% Monday 21:10`), empty and
trailing-space slots all reject. The §5.14 pattern accepts `1789330000 +0000` / `1789330000 -0530`
and rejects the empty string, a bare epoch, `+05:30` and a named zone.
