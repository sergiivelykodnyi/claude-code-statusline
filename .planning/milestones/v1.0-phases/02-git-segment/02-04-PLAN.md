<objective>
Close the second-round Phase 2 verification blocker: a confirmed command-injection RCE (CR-02)
on the primary interpreter /bin/bash 3.2.57, plus its regression-net hole (WR-04) and the
adjacent fail-silent breach (WR-03).

An ARRAY-valued JSON value in any of the three string fields the single jq `@sh` program
ingests — `.model.display_name`, `.effort.level`, `.workspace.current_dir` — makes `@sh` emit
one quoted word PER ARRAY ELEMENT (`MODEL='' 'touch' '/path'`), and `eval "$vars"` in
`main()` parses that as an assignment prefix followed by a command. Reproduced live for all
three fields: marker created, exit 0, zero stderr. Plan 02-03 guarded only the 7 numeric
fields with `numbers`; its threat register accepted `current_dir` as "already mitigated by @sh
quoting" — an assumption that holds for scalar strings only and is falsified by the array
form. The 95/95 harness cannot see it: every injection probe uses a STRING payload.

This plan mirrors 02-03 exactly: enforce STRING type at the same single jq boundary on the
three string fields, so every non-string collapses to the empty string and eval only ever
sees one quoted word per assignment; then add array-payload probes for all 10 ingested
fields so this vector can never silently pass again. As an explicit, separately committed
third task it also canonicalizes the 7 numeric fields to bash-safe non-negative integers
(WR-03) so well-typed floats/exponents stop leaking arithmetic errors to stderr.

Purpose: eliminate a silent arbitrary-local-command-execution defect in the shared
render/ingestion path the git segment consumes (PORT-02 render contract, GIT-06 degradation
contract) without regressing any verified Phase 2 behavior.
Output: hardened statusline.sh jq boundary (10/10 fields type-guarded) + array and
non-integer probes in tests/run.sh.
</objective>
